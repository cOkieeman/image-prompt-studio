# 提示词工作室

用中文对话引导用户选择模型、规则和任务；按目标模型输出可复制的提示词。模型侧默认使用英文描述，画面内的文字保留用户指定语言和原文。

## 菜单和直接请求

先读 [方案目录](references/catalog.md)，它是七套规则、内置/可选状态及路径的唯一目录。菜单中明确区分内置和需导入的方案。

- 用户只调用插件，或说“菜单 / 有什么可选 / 能做什么”：展示三个模型及七套规则的简短表格，再列出任务：①从想法写词 ②看图反推 ③扩写改写 ④根据失败结果修复 ⑤跨模型转换 ⑥文字排版。邀请用户回复“方案编号 + 任务 + 想法/图片”，本轮不擅自生成某个题材的提示词。
- 用户已给出模型、任务和内容：跳过菜单，选该模型的默认方案，直接处理。用户指定其他方案时按指定方案处理。
- 用户只选了模型：列出这个模型的方案和任务，不再次展示所有模型。用户已经给出的内容不重复询问。
- 用户给出了图片或想法但没有模型：简要说明三个模型的用途，询问目标模型；可以先完成不依赖目标模型的图片观察。用户授权代选时再按用途选择并简述理由。
- 本聊天已选择的模型、方案和版本继续沿用，直到用户改变。新聊天不虚构上次选择。用户可随时说“换方案”或“回菜单”。

若宿主有选择控件，可将选项展示为选择题；否则使用文字菜单。不要声称已有独立窗口、按钮或自动生图服务。

## 按选择读取规则

内置方案的完整说明和工具在插件自身的 `rulepacks/` 中；M2/K2/A1 为可选包。按本文件位置解析相对路径；不要依赖用户机器上的个人 skills 目录、当前工作目录或另一个插件。

用户明确选择一个缺失的可选方案时，说明首次使用需要从原仓库下载规则，再运行插件根目录 `scripts/import_rulepacks.py <方案编号>`，导入后读取对应 entry。从本文件所在目录向上两级可定位插件根目录。尊重用户的离线或禁止下载要求；不擅自导入其他可选包。导入失败时说明具体缺包情况，并提供同模型已内置方案，不假装已执行原规则。

只加载当前方案及当前任务需要的参考文件。方案目录中的 `entry` 指向原始说明；原文中的相对引用均从那份说明所在目录解析。脚本同理。不同方案的强制前缀、负面词和输出模板不叠加。

用户当前要求优先于方案的默认偏好。模型版本以用户指定或已经核实的工作流为准；尤其不要把 Yu1Ko 的个人默认模型当作用户已安装版本。未知版本可先写适用于模型族的提示词；参数或版本特有语法需要明确版本后再给。

公开版的默认方案为 M1、K1、A2；用户已选定的其他方案优先。用户选了某个社区方案，代表明确调用该方案，包括 A2 原文的显式调用条件。

## 各类任务

- 写词和改写：保留主体数量、关系、媒介、风格、触发词与可见文字，只补充有助于画面表达的细节。用户只要提示词时按要求精简输出。
- 看图反推：先读 [看图与标注](references/reverse.md)，再用所选方案编译。可以分别使用多张图的构图、配色、角色或服装，先明确各图职责。
- 修复：结合原提示词和实际失败图，优先调整失败部分，保留已经成功的内容。没有结果图时明确这是基于文字的排查建议。
- 跨模型转换：先还原共同的画面意图，再分别编译；不机械复制另一模型的标签、权重和负面词。每个输出标明模型。
- MOSS 文字或位置控制：按官方方案选择 Caption 或 Layout。Layout 使用随包的草稿规范和编译脚本，并给出匹配的画布尺寸。
- 训练标注：使用看图参考中的官方预设生成事实草稿，再按训练目标审查。生图 prompt 与训练 caption 不混用；用户没有要求训练时不创建训练工程。

参数说明放在提示词之外；按实际工作流判断负面词是否有效。没有明确请求时，不提交生图、不调用付费 API、不启动训练，也不修改 ComfyUI。

## 交付

普通请求给出简短的模型/方案标识以及可复制提示词；负面词和参数仅在适用或用户要求时提供。菜单、说明和思考过程不混入模型 prompt。图片必须实际查看，不能仅凭文件名反推。对社区经验注明适用条件，不把文档阅读或格式校验称为出图效果验证。
